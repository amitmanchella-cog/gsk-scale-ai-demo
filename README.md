# GSK Scale AI demo kit — Field Force Navigator

Synthetic pharma **field-force** data (territories, reps, HCPs, visits, follow-ups, weekly sales) and three
connected Devin use cases that tell one story:

| Order | Use case | What Devin does | Where |
|---|---|---|---|
| 1 | **UC1 — build the data** | Converts a messy pandas/PySpark notebook into a tested, modular PySpark job with DQ checks, a Databricks job spec and a parity check against the notebook's output. Saved as a reusable **playbook**. | `notebooks/` → `pipelines/territory_kpis/`, `jobs/` |
| 2 | **UC4 — build the product** | Runs the full phase-gated SDLC from a Jira PRD: requirements → design → build → verify → gated release of the **Field Force Navigator** call planner, consuming UC1's curated tables. | `apps/navigator/`, `docs/uc4/` |
| 3 | **UC3 — run it** | A Devin **Automation** watches CI on this repo; on a red check it diagnoses from logs, reproduces, adds a failing regression test, fixes, and comments the root cause — scoped to this repo with an ACU cap. | `services/supply_api/`, `.github/workflows/` |

Devin here is **managed infrastructure and governance** — playbooks and Automations that scale org-wide, help
less-experienced engineers and SIs ship safely, and complement (not compete with) GSK's agentic factory.

> All data is synthetic and generated by `data/generate.py` (seeded). No real people, products, places or CRM data.

## Layout

```
data/                     generate.py + ~10k rows of Parquet (6 tables)
notebooks/                territory_kpis.ipynb (UC1 "before"), hcp_engagement.ipynb (live run), expected_output/
pipelines/territory_kpis/ UC1 output: modular PySpark job, tests, DQ checks, parity.py
jobs/                     Databricks job JSON (shown, not run — no Databricks account needed)
apps/navigator/           UC4 output: FastAPI backend + React/Vite frontend
services/supply_api/      UC3: FastAPI clinical-supply forecast service used to demo CI self-healing
docs/                     DEMO_FLOW_UC1.md, DEMO_FLOW_UC4.md, DEMO_FLOW_UC3.md, DEMO_RUNBOOK.md
.github/workflows/        CI: ruff + pytest for every code folder, plus UC1 parity
```

## Run locally

```bash
pip install -r requirements-dev.txt
python data/generate.py            # regenerate data (deterministic)
ruff check . && pytest             # what CI runs
cd notebooks && python run_notebook.py territory_kpis.ipynb   # rebuild expected_output/
```

Tests and parity run on **local Spark** in CI; nothing here needs Databricks, a cloud account or credentials.
